# Правила работы в этом репозитории

Это боевое приложение. Оно торгует настоящими деньгами на Coinbase и крутится
на Kamatera по адресу `103.90.162.77:3847`, откуда владелец открывает его с
ноутбука и с телефона. Здесь нет стенда: то, что попало в `master` и
задеплоено, сразу работает с реальным счётом.

Ниже — правила, выведенные из уже случившихся поломок. Каждый пункт написан
после того, как что-то сломалось на живом сервере.

---

## 1. Изменения в один конец

Есть правки, которые нельзя откатить после выкатки, потому что они отключают
сам механизм выкатки или доступ к приложению. Их нельзя делать никогда, пока
владелец не подготовит сервер.

### `DEPLOY_KEY` — не убирать запасное значение

```js
const deployKey = DEPLOY_KEY || 'trading-deploy-2026';   // НЕ ТРОГАТЬ
```

Убиралось дважды. Выглядит как дыра в безопасности, и формально это она. Но:

- деплой идёт **только** через `POST /api/deploy` — SSH на машину нет;
- в `.env` на сервере переменной `DEPLOY_KEY` нет;
- без запасного значения обработчик отвечает `503` — и код на сервер больше
  доставить нечем, включая откат этой самой правки.

Секретности удаление не добавляет: ключ лежит в истории git и всё равно
подлежит ротации.

Правильный порядок: владелец добавляет `DEPLOY_KEY` в `.env` на сервере →
перезапуск → **только потом** строка убирается.

### `HOST` — не ставить `127.0.0.1` по умолчанию

```js
const HOST = process.env.HOST || '0.0.0.0';   // НЕ МЕНЯТЬ значение по умолчанию
```

Приложение по замыслу открывается снаружи. `127.0.0.1` по умолчанию — разумно
для ноутбука и смертельно здесь: переменной `HOST` на сервере нет, после
рестарта `103.90.162.77:3847` перестаёт открываться совсем, и чинить это опять
нечем.

### Общее правило

Перед правкой конфигурации спроси себя: **если это выкатить и оно окажется
неверным, чем я это откачу?** Если ответ «ничем» — не выкатывай. Новую
переменную окружения вводи так, чтобы её отсутствие сохраняло текущее
поведение.

## 2. Файлы, которые нельзя коммитить

В корне лежат файлы с живыми данными. Работают два разных механизма, не путай
их.

**Отслеживаются git, но защищены при деплое.** Список `PROTECTED` в обработчике
`/api/deploy`: копия снимается до `git pull` и возвращается после, потому что в
репозитории лежат устаревшие версии этих файлов.

```
settings.json  profit-history.json  favorites.json
selected-orders.json  selected-coin.json
notified-fills.json  score-history.json
```

Один коммит, случайно затронувший `settings.json`, заменит живой токен Telegram
на пустой — защита спасёт сервер, но в репозиторий уедет мусор. Если такой файл
появился в `git status` — не коммить его, убери из индекса.

**Не отслеживаются вовсе.** Остальное состояние (`scalp-lab.json`,
`paper-trades.json`, `trade-journal.json`, кеши) сидит в `.gitignore`, `git
pull` его не трогает, и в `PROTECTED` оно не нужно. Не добавляй их в git —
именно так журнал лаборатории и превратится в чужие данные.

**Исключение:** `scalp-gate-validation.json` коммитить **нужно**. Его отпечаток
привязан к коду гейта, поэтому он обязан ехать на сервер вместе с этим кодом. В
`.gitignore` для него стоит отдельное исключение — не убирай его: без файла
сервер считает проверку отсутствующей и блокирует входы навсегда.

---

## 3. Кодировка: пиши текст интерфейса через файл

Русские строки уже дважды приезжали в виде `?????????` — один раз съело заметку
поколения в журнале, второй раз кнопку, алерт и карточку статуса в
лаборатории. Причина: текст проходит через shell или через `print` в cp1252 и
теряет кириллицу.

Правила:

- строки с кириллицей записывай **файловым инструментом**, не через `sed`,
  `echo` или heredoc в оболочке;
- обратные слэши в оболочке схлопываются — `\n` и `\uXXXX` в аргументах
  ломаются; если нужен escape, пиши скрипт в файл и запускай файл;
- перед коммитом проверь: `git diff | grep "?????"` должен быть пуст.

---

## 4. Две вёрстки, обе обязательны

Интерфейс существует в двух файлах:

- `public/index.html` — десктоп;
- `public/mobile/index.html` — телефон.

Они не переиспользуют код. **Любая правка логики отображения должна попасть в
обе.** Уже было: блокировка входов появилась только на десктопе, и телефон
продолжал показывать «ВХОД» там, где большой экран писал «НЕ ПРОВЕРЕНО» — то
есть звал в сделку, которую система только что запретила. Это опаснее, чем не
делать правку вовсе.

Проверять так: `grep` по новому символу в обоих файлах.

---

## 5. Отпечаток гейта обнуляет статистику

`gateFingerprint()` хэширует `src/scalp/index.js` и `src/scalp/scanner.js` без
комментариев и пробелов. Смена отпечатка закрывает поколение лаборатории:
накопленные бумажные сделки уходят в архив, счёт начинается с нуля.

За пять дней так сгорело четыре поколения — 13, 16, 50 и 20 сделок, ни одно не
дожило до выборки, по которой можно судить.

**Не правь логику гейта без необходимости.** Комментарии и подписи условий
менять безопасно (они вырезаются из хэша), сам код — нет. Если правка нужна,
скажи об этом прямо: она стоит текущей когорты.

---

## 6. Порог входа и потолки баллов

Инвариант: **86+ ⇔ вход**, мёртвая зона 75–85 пуста. Ломать нельзя — на нём
держится и интерфейс, и алерты.

Отдельно про потолки. Условие может быть жёстким (участвовать в `pass`), но
при этом **не должно** ронять балл монеты, для которой оно не решает исход.
Пример уже случившейся ошибки: спред сделали жёстким условием, а сканер
запрашивает стакан только у кандидатов (`rangePos < 0.4 && aboveE9`) ради
лимита Coinbase. В итоге 37 монет из 40 получили «спред неизвестен», схлопнулись
в общий балл 44 и список ожидания перестал ранжироваться.

Правило: потолок применяй только когда **все прочие условия выполнены** — то
есть когда проверка действительно определяет исход.

---

## 7. Не хардкодь результаты замеров в комментарии

В комментариях и подсказках интерфейса стояли числа вроде «68% побед, +0.2% на
сделку, 28 252 сэмпла». Гейт с тех пор менялся десять раз, числа остались и
врали. Сейчас единственный источник — `scalp-gate-validation.json`, привязанный
к отпечатку. Не возвращай статические эталоны в код.

---

## 8. Отсутствие данных — это запрет, а не разрешение

Сквозной принцип. Неизвестный спред, непосчитанный режим BTC, отсутствующий
прогон — всё это **непройденное условие**, никогда не «можно». Проверяй, что
`null` и `undefined` не проваливаются в ветку разрешения.

Отдельно: пустой массив — это «неизвестно», а не «пусто». Уже было: сразу после
перезапуска сканер ещё не отдал состав условий, диф сравнил поколение с пустым
списком и отчитался об удалении всех девяти условий разом.

---

## 9. Проверяй то, что запускается, а не только синтаксис

`node --check` ловит опечатки, но не ловит главного. Перед выкаткой подними
сервер на свободном порту и убедись, что он вообще стартует:

```bash
PORT=3999 HOST=127.0.0.1 node server.js
curl -s http://127.0.0.1:3999/api/lab
curl -s http://127.0.0.1:3999/api/scalp-scan
```

Так поймались бы, например, обращения к `scalpScan.validation.n`, когда объект
ещё `null`: исключение уходило в собственный `catch`, и алерт молча не
отправлялся. Немые поломки здесь опаснее шумных — Telegram молчит одинаково и
когда сигналов нет, и когда код падает.

**Осторожно:** не дёргай `POST /api/deploy` на локальном репозитории. Он делает
`git pull` и при конфликте отбрасывает незакоммиченные правки.

---

## 10. Обязательные проверки перед коммитом

```bash
node scripts/audit-live.js     # 41 утверждение по живому серверу
node scripts/verify-score.js   # независимый пересчёт баллов
```

Оба ходят по HTTP и ордеров не ставят. `verify-score.js` повторяет формулу
баллов вручную — **при изменении гейта его надо править вместе с гейтом**,
иначе он ругается на себя. То же с `audit-live.js`, когда меняется форма
ответа API: он уже трижды падал на переименованиях, а не на дефектах.

Если проверка упала — сначала пойми, сломано приложение или устарел тест. Не
подгоняй тест под поведение, не разобравшись.

---

## 11. Убирай за собой мёртвый код

Сейчас в `server.js` лежат `labTick`, `labTickLegacy`,
`scalpValidationStatusLegacy`, в `lab.js` — `sweepTargetsLegacy`. Ни одна не
вызывается. Заменяешь реализацию — удаляй старую, а не оставляй рядом с суффиксом
`Legacy`: в следующий раз кто-то будет читать и править не ту.

---

## 12. Деплой

```bash
git push origin master
curl -s -X POST "http://103.90.162.77:3847/api/deploy?key=trading-deploy-2026"
```

Сервер сам делает `git pull` и `process.exit(0)`, pm2 поднимает заново.
**Сервер тянет с GitHub** — незапушенный коммит не задеплоится.

Успешный ответ не значит, что приложение поднялось. После деплоя проверь:

```bash
curl -s -o /dev/null -w "%{http_code}" http://103.90.162.77:3847/
curl -s http://103.90.162.77:3847/api/scalp-scan
curl -s http://103.90.162.77:3847/get-balance
```

Скан появляется примерно через 90 секунд после старта, режим BTC — через 75.
До этого `regime` равен `null`, и проверки на нём падают: это не поломка,
подожди.

---

## Если сомневаешься

Спроси владельца, а не выкатывай. Цена ошибки здесь — не упавший тест, а
недоступное приложение, потерянный токен или сделка на реальные деньги.
